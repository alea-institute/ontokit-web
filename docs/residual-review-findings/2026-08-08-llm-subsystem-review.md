## Overall verdict

**Not deployable to FOLIO DEV in its current state — not even for user testing.** Three independent P0s mean the core loop does not work at all against a real database: every suggestion save raises `AttributeError` (P0-1), every approve/reject violates a DB CHECK constraint (P0-2), and LLM generation is unreachable from the UI because the model can never be set (P0-3). These are not edge cases; they are the happy path. The 592 green unit tests are structurally blind to all three: the missing git method is mocked into existence, the CHECK constraint never exists in mocked sessions, and no test drives the settings form against the real config route.

The deeper pattern the user suspected is real: the hand-written decision logic (budget math, role gates, token verification, anonymous hardening) is genuinely good — several personas independently called out unusually adversarial tests and careful redaction. But every boundary where that logic meets a provider, the database, git, or a second concurrent request is unverified, and that is where all six P0s live. Fix the P0s, add one end-to-end smoke test (create session → save → submit → approve against real Postgres + a fake provider), and re-review the P1 cost/trust items before any deployment with real keys.

## P0 — Blockers

### P0-1 · `commit_to_branch` does not exist; every suggestion save path raises AttributeError
`API/ontokit/services/suggestion_service.py:329, 1226, 1386` → injected `BareGitRepositoryService` (`ontokit/git/__init__.py:22`) defines only `commit_changes` (`ontokit/git/bare_repository.py:927`). No definition, no `__getattr__` fallback, anywhere. Each call site carries `# type: ignore[attr-defined]` — mypy flagged it and was silenced. Tests pass because `test_suggestion_service.py:732` *creates* the attribute on a mock.
**Failure:** any save (`PUT .../sessions/{id}/save`), beacon flush, or anonymous save → `AttributeError` → caught by broad `except` → 500. Suggestion editing is entirely non-functional. (Pre-existing from commit `2cd425ca`, but squarely in this surface.)
**Fix direction:** call `commit_changes` with its real signature; add one integration test that commits through the real git service.

### P0-2 · DB CHECK constraint forbids `merged`/`rejected`/`changes-requested`; every review terminal action fails at commit
`API/alembic/versions/l0g1h2i3j4k5_add_suggestion_sessions_table.py:38-41` creates `ck_suggestion_session_status` allowing only `active/submitted/auto-submitted/discarded`. No later migration widens it (verified across all versions). The model enum (`ontokit/models/suggestion_session.py:25-27`) and the service (`suggestion_service.py:982, ~1049, ~1080`) write the other three.
**Failure:** on any alembic-migrated Postgres, approve → PR merged externally (irreversible) → `IntegrityError` at `db.commit()` → 500 + rollback of session status, outcome row, and trust promotion. `auto_accept_ripe_sessions` hits it in a loop, retrying the merge of an already-merged PR each sweep. Tests never see it (mocked sessions; model declares no CheckConstraint, so `create_all` schemas lack it).
**Fix direction:** migration to widen the constraint; declare the constraint on the model so test schemas match.

### P0-3 · LLM generation is unreachable from the web UI: the model can never be set
WEB `components/projects/LLMSettingsSection.tsx:271-280` sends `model_tier`, never `model`; no model picker exists anywhere (`llmApi.getKnownModels`/`getProviders` have zero callers). API `routes/llm.py:228` writes `config.model` only if provided; there is no tier→model resolution anywhere (verified: `model_tier` appears in no generation/registry code path). `routes/generation.py:164-168` then 400s on `not config.model`. The gate lies: `routes/llm.py:355-368` computes `configured` from key/local only, so `useLLMGate.canUseLLM` is true.
**Failure:** owner configures provider+key, sees "AI settings saved", Suggest buttons enabled — every click returns 400, rendered as generic "Could not generate suggestions. Retry" (`ClassDetailPanel.tsx:668-672`). Unrecoverable from the UI.
**Fix direction:** either resolve model server-side from `model_tier` per provider, or ship the model picker; make `llm-status.configured` require a resolvable model.

### P0-4 · Failed PR merges are recorded as successful merges and mint ACCEPTED trust credit — and for editors and the auto-accept sweep, the merge *always* fails
`API/ontokit/services/suggestion_service.py:979-992`: `except HTTPException: logger.warning(...)` then `status='merged'` + `_record_terminal_outcome(ACCEPTED)` (feeds `evaluate_promotion`). `merge_pull_request` requires role in `("owner","admin")` with no superadmin escape (`pull_request_service.py:520-526`), but `_can_review` admits **editor** (`suggestion_service.py:824-825`), and the auto-accept system actor (`:1669-1680`) has no member row → role `None` → guaranteed 403, swallowed.
**Failure:** every editor approval and every auto-accepted trusted suggestion marks the session merged while the ontology never changes and the PR stays open; contributors are promoted to trusted (and thence auto-accept eligibility) on merges that never happened. Interacts with P0-2: where the constraint exists, the status write then also blows up.
**Fix direction:** let merge failures propagate (or mark a distinct `merge_failed` state); give the system actor and reviewers an authorized merge path.

### P0-5 · Unauthenticated users trigger paid embedding calls on the project owner's key
`API/routes/semantic_search.py:52` and `routes/duplicate_check.py:26` take `OptionalUser`; access is `project_service.get` → `_can_view` (`project_service.py:1119-1120`) returns True for any public project before the user check. Both reach `provider.embed_text(query)` (`embedding_service.py:531-532, 602-603`). Verified: `check_budget`, `check_rate_limit`, and `log_llm_call` each have exactly one caller — all in `generation.py`. Embedding spend is invisible to budget by construction.
**Failure:** public project with `provider=openai|voyage`: an unauthenticated loop over `GET .../search/semantic?q=...` burns the owner's key with no auth, no rate limit, no budget, no audit row; `/llm/usage` shows $0.
**Fix direction:** require auth + a role gate on both routes (or force `local` provider for anonymous reads); route embedding calls through budget + audit.

### P0-6 · The duplicate check cannot block: identical labels return "pass"
`API/ontokit/services/duplicate_check_service.py:24-30, 103-150`: composite = 0.40·exact + 0.40·semantic + 0.20·structural; verdicts require `> 0.80` (warn) / `> 0.95` (block). Structural (`structural_similarity_service.py:38-53`) is Jaccard over the **public FOLIO graph** via folio-python and returns 0.0 when either IRI is absent (always true for a freshly minted suggestion IRI), when folio-python is missing, or when `parent_iri` is None (all `parents`-type suggestions: `suggestion_generation_service.py:289`). With structural=0 the ceiling is exactly 0.80 → `0.8 > 0.80` is False → **"pass"**. Realistic identical-label cases (semantic ≈0.9) score ≈0.76. Block additionally needs structural > 0.75 — effectively unreachable. The three block/warn tests patch `compute_similarity` to constants, hiding the ceiling.
**Failure:** suggester proposes "Legal Entity" in a project that has "Legal Entity" → verdict pass, UI's `disabled={verdict==="block"}` never fires, duplicate class minted and merged.
**Fix direction:** renormalize weights when structural is unavailable (or make thresholds `>=`); compute structure from the project graph, not public FOLIO; assert the identical-label case in a test without patching structural.

## P1 — Should fix before real-key deployment

### Cost / budget
- **P1-1 · Unknown model or pricing-fetch failure silently disables the entire budget.** `llm/pricing.py:95-96` returns `(0.0,0.0)` on lookup miss; `_fetch_and_cache` (`:43-50`) swallows failure with no negative caching, so an unreachable `raw.githubusercontent.com` also means every request pays a fresh 15s timeout, then prices at $0. `generation.py:315-319` writes `$0` audit rows → `check_budget` never fires, dashboard reads $0.00 while the real bill runs. Fix: fail closed (or loudly) on unpriced models; negative-cache fetch failures.
- **P1-2 · Embedding spend is entirely unmetered, and the only guard is bypassable.** `routes/embeddings.py:96` (editor+) enqueues full-ontology embeds; the in-flight guard is per `(project, branch)` with caller-supplied `branch` (`:93, 102-117`) — one re-embed per session branch, concurrently. No budget/rate/audit on any `embedding_service` provider call (incl. the per-suggestion dedup fan-out inside metered generation, `suggestion_generation_service.py:161`). Fix: budget + audit on embedding calls; cap concurrent jobs per project.
- **P1-3 · Missing `usage` in provider responses records zero tokens.** `llm/openai_compat.py:71-73` (covers openai/groq/xai/custom/…) and `anthropic_provider.py:70-71` have no fallback (Google/Cohere estimate by word count). A paid gateway that omits `usage` bills upstream and audits $0. Fix: estimate-on-missing like the other providers.

### Security
- **P1-4 · RDF injection: LLM-supplied IRIs reach committed Turtle unescaped.** `suggestion_generation_service.py:281` (parents `iri`), `:297` (edges `target_iri`), annotations `property_iri` — no IRI-syntax validation anywhere (`validate_entity` deliberately None for these types). WEB `lib/ontology/turtleUtils.ts:64` emits `<${iri}>` raw (string literals are escaped; IRIs are not), consumed by `turtleClassUpdater.ts:60,77,81`. A crafted "IRI" containing `> . <...> owl:imports <http://attacker/evil.ttl> . <` breaks out and appends attacker triples on Accept. Fix: validate IRI syntax server-side at parse time (reject whitespace/angle brackets/quotes); escape or reject on the web serializer too.
- **P1-5 · Prompt injection from ontology content is unmitigated.** All five prompt builders interpolate labels/annotations raw (`llm/prompts/annotations.py:83`, `parents.py:62`, `edges.py:74-78`, …); `_parse_json_safe`'s greedy `\{.*\}` regex salvage (`suggestion_generation_service.py:372-391`, untested) will extract an injected JSON block from prose. Combined with P1-4, a low-trust suggester's merged annotation can steer a later editor's suggestions into malicious structured output. Fix: delimit untrusted values, cap lengths, and validate output relatedness.
- **P1-6 · AnthropicProvider silently drops `base_url` and bypasses the SSRF-hardened client.** `llm/anthropic_provider.py:44` builds `AsyncAnthropic(api_key=...)` only; `registry.py:240` passes base_url and it is discarded. Every other provider uses `secure_async_client`. A proxy/data-residency config green-lights on test and then ships keys + ontology context to api.anthropic.com. Fix: pass `base_url=` and `http_client=secure_async_client(...)`.
- **P1-7 · The R8 entity-minting trust gate is declarative — and the web never sends the flag.** `schemas/suggestion.py:28-34` `mints_entity: bool = False`, enforced only `if data.mints_entity` (`suggestion_service.py:315-316`); WEB never sets it (zero grep hits). Since `content` is full client-supplied Turtle, any contributor mints classes past the trust gate. Fix: detect minting server-side by diffing the Turtle, not by trusting a client flag.

### Correctness / concurrency
- **P1-8 · Git branch locks are per-process; prod runs `--workers 4`.** `suggestion_service.py:67` module-level `asyncio.Lock`s; `Dockerfile.prod:56`. `write_file` (`bare_repository.py:195-264`) is read-modify-write on the branch tip with no compare-and-swap → concurrent save + beacon flush on different workers silently drops a commit. Fix: pg advisory lock keyed on (project, branch), or CAS on the ref.
- **P1-9 · Lost updates on session counters.** Session loaded at `suggestion_service.py:304`, lock taken at `:325` — `changes_count += 1` and the `entities_modified` JSON round-trip operate on stale snapshots; concurrent saves lose increments and clobber the entity list (PR body omits entities). Fix: SQL-level `changes_count = changes_count + 1`; move reads inside the critical section.
- **P1-10 · Beacon flush always 401s.** WEB `lib/hooks/useSuggestionSession.ts:69-72` sends `session_id` where an HMAC beacon token is required (`SuggestionSession` TS type omits `beacon_token`, which the API returns — `schemas/suggestion.py:11-19`). The API's own comment at `anonymous_suggestions.py:166-169` records this exact bug being fixed on the anonymous side only. The advertised tab-close safety net silently discards the last edit. (Currently masked by P0-1 — the flush would 500 anyway.) Fix: plumb `beacon_token` through the TS type and hook.
- **P1-11 · Duplicate detection is blind to its target scenario.** Suggestion branches are never embedded (only the project source-save route and manual jobs enqueue embeds; `suggestion_service.save()` enqueues nothing) and merges never re-embed `main` (`_approve_unchecked` bypasses even the index refresh the PR route does). Two parallel "Contract" suggestions both pass; yesterday's merged entity is invisible to today's check (`check()` short-circuits verdict=pass on zero candidates, `duplicate_check_service.py:70-76`). Fix: embed on suggestion save (or at submit); enqueue embed+index jobs post-merge on every merge path.
- **P1-12 · No server-side enforcement on the write path at all.** `save()` commits arbitrary unparsed Turtle (`data.content.encode()` straight to git — no rdflib parse anywhere before commit); dedup verdicts and ValidationService run only inside LLM generation for display; `submit()`/approve run neither; the only "block" is a disabled button in the browser. A malformed commit merges to `main` and breaks every subsequent load/index/lint/embed. Also: no rule checks a parent IRI exists (VALID-03 returns clean for unknown IRIs, `ontology_index.py:735-736`). Fix: parse Turtle server-side on save; re-run dedup+validation at submit as a gate, not a decoration.

### Frontend
- **P1-13 · One click can bill three LLM generations.** `lib/api/generation.ts:70-82` omits `retryOn5xx`, defaulting true (`client.ts:41`) despite the client's own docstring requiring actuations to pass false; the route deliberately 500s on post-call pipeline bugs (`generation.py:304-310`), so retries re-bill and re-consume rate limit with no audit rows. Same exposure on `approve`/`bulkReview` (which merge PRs). Fix: `retryOn5xx: false` on all actuations.
- **P1-14 · Suggestion store leaks across projects.** `lib/stores/suggestionStore.ts:12-15` keys by `${entityIri}::${type}` — no project, no branch — and `clearSuggestions` has zero callers. Forked vocabularies share IRIs by design here: project A's pending suggestions render (and Accept-write) into project B's editor for the same IRI. Fix: key by project+branch+IRI; clear on project switch.
- **P1-15 · All distinct API errors collapse to one generic dead-end.** 402 budget / 403 role / 429 rate / 400 no-model / 502 provider are all rendered as "Could not generate suggestions. Retry" (`ClassDetailPanel.tsx:668-672`; no hook inspects `ApiError.status`); `useLLMGate.invalidateStatus` — documented "call after 402" — is called from nowhere, so the budget banner lags ≥60s. Fix: branch on status; invalidate llm-status on 402/429.

## P2 — Worth fixing

- **SSRF `custom` opt-out:** any authenticated user's own project can set `provider=custom` + private base_url → server dials internal hosts and returns upstream error bodies (`ssrf.py:36`, `registry.py:266-268`, `llm.py:306-310`). Gate local providers behind an instance setting.
- **SSRF transport doesn't pin the resolved IP** (`ssrf.py:226-234`) — validates, then lets httpx re-resolve; DNS-rebinding window remains despite the docstring's claim. Multi-A-record answers also untested.
- **Budget TOCTOU:** check at `generation.py:201`, record at `:320` — N concurrent requests at 99% all pass (owners are rate-unlimited). Plus the whole LLM call + per-suggestion embeds run inside one open DB transaction (connection pinned idle-in-transaction for the full provider wall-clock).
- **Failure paths spend for free:** post-chat pipeline errors and client disconnects skip the audit write (`generation.py:266-335`); rate-limit tokens aren't refunded on 402.
- **`test_connection` is a real billable call with no audit row** (`llm.py:246-310`; owner/admin, `max_tokens=1`) — reconciled severity between personas: cost negligible, audit-trail gap real.
- **Embedding pipeline integrity:** SELECT-then-INSERT upserts race the unique constraint and fail whole jobs (`embedding_service.py:352-380, 469-497`); a failed job leaves a half-fresh index that search still trusts; the prune deletes concurrently-added embeddings; `status == "complete"` vs written `"completed"` (`:203` vs `:407`) makes coverage always report 100%; incremental auto-embed never prunes deletes; switching config to openai/voyage 500s (provider built with `api_key=None` before the new key is applied, `embedding_service.py:130-142`).
- **HNSW index silently absent:** dimensionless `vector` column (`n2o3p4q5r6s7:78`) can't take an HNSW index; the migration wraps failure in `RAISE WARNING` (`v9w0x1y2z3a4:62-75`) → sequential scans forever; no dimension check across providers → mixed-dim rows make the ANN query throw, which dedup fail-soft converts to "pass".
- **`duplicate_rejections` is write-never:** no code constructs a row and no candidate is ever suppressed by one — the D-10 mechanism described in the migration does not exist.
- **Quality jobs are read-gated and unthrottled** (`quality.py:68-75, 211-219`): any authenticated user can queue-flood full-graph consistency/duplicate jobs on public projects (compute DoS; no 409 guard unlike embeddings).
- **Fail-soft gates have no tests and no alerting:** dedup infra failure → verdict "pass", validation failure → empty errors list (`suggestion_generation_service.py:150-151, 171-177`) — both uncovered.
- **React Query retries 4xx four times** (no `retry` config, `app/providers.tsx:20-30`): `useLLMConfig` hits a by-design 404 → 4 fetches + ~7s spinner on every unconfigured settings load; `useSemanticSearch`'s bare `catch {}` silently degrades 401/403/500 to text fallback (up to 12 fetches).
- **`daily_remaining` is a static per-role constant** (`llm.py:394`) that the gate treats as a live count (`useLLMGate.ts:34-36`); its own comments (0-means-consumed, "server 402s") are both wrong (viewer=0, limiter 429s).
- **Trust limiter TTL bug:** `trust_rate_limiter.py:98-100` INCR-then-EXPIRE without `nx=True` — a crash between them permanently blocks the contributor (the LLM limiter fixed exactly this).
- **Crypto KDF:** unsalted single-round SHA-256 of `SECRET_KEY` with no length floor (`llm/crypto.py:32`) — brute-forceable at hash speed against exfiltrated blobs. (Fernet IV handling, rotation, and default-secret refusal are all correct.)
- **PR-submit idempotency:** no unique index on `(project_id, source_branch)` behind the check-then-act (`suggestion_service.py:502-522`) — double-tap submits create two PRs; retry rollback in `_create_pr_directly` (`:617-623`) discards anonymous submitter credit + verification flags.
- **Web type drift (minor):** `EmbeddingProvider` includes `"anthropic"` which the API rejects (`embeddings.ts:7` vs `schemas/embeddings.py:9`); `useLLMConfig` cache key not user-scoped unlike siblings.

## Test adequacy (summary)

Where the suite engages it is unusually good — budget tests assert against compiled SQL, route tests pin 429-before-provider ordering, anonymous tests check the OpenAPI schema doesn't leak honeypot semantics. But: every provider adapter is at 0% coverage; `validate_base_url` (the actual config-write SSRF gate) is 0%; `update_llm_config`/`test_connection` routes are untested; `_parse_json_safe`'s failure ladder, both fail-soft gates, the anonymous rate limiter, and the cross-branch pgvector query (0%) are uncovered; `log_llm_call` is never invoked by any test. Every layer is tested against a mock of the adjacent layer; the three P0 breakages (mocked-into-existence git method, absent CHECK constraint, unreachable model config) are precisely the class of bug this structure cannot see. Highest-leverage additions: one real-Postgres end-to-end suggestion lifecycle test, one real-git commit test, one settings-form→generate contract test, and adversarial tests for pricing-miss and missing-usage.

5. **Overlapping claims deduplicated** (pricing $0 appeared in three reports; TOCTOU budget in three; Anthropic base_url in two; each appears once above at the highest verified severity).
